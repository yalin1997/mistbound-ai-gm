# 霧海紀事 · AI GM 遊戲 MVP

一台裝置即可遊玩的繁體中文原創 D20 網頁冒險，支援單人與 2–4 人網路合作。AI 是可切換的行動理解／旁白服務；骰點、效果、任務與存檔由伺服器決定。

## 在私人電腦試玩

安裝 Node.js 24.5 以上（建議最新 Node.js 24 LTS）與 Git，clone 此儲存庫後在專案目錄執行下方啟動命令。Windows、macOS 與 Linux 使用相同的 `npm` 命令；不要使用 GitHub Pages 啟動，遊戲需要 Node 後端。

不設定 AI 金鑰也能完成規則試玩；需要真實 AI 時再按「AI 模式」一節設定。多人遊戲需要每位玩家使用不同帳號，在同一網路可用主機區網 IP 加 `:3001` 連線；遠端跨網路則需要另外提供可達的 HTTPS/WSS 服務。

獨立驗收報告位於 [acceptance/independent-playtest-report.md](acceptance/independent-playtest-report.md)。目前兩項 P2（防禦提前清除迷茫、第二章沿用戰鬥順序）**已確認但尚未修復**，可試玩但不要將結果視為完整 AI 遊戲驗收通過。驗收用 SQLite、登入資料、`.env`、node_modules 均不在儲存庫中。

## 啟動

需求：Node.js 24.5 以上、npm。無需安裝資料庫服務。啟動命令使用 Node 的環境代理支援，保留既有 proxy 與 CA 設定。

```bash
npm ci
npm run build
npm start
```

開啟 <http://localhost:3001>，建立帳號 → 單人啟程或建立合作房間 → 建立角色 → 準備 → 開始。合作房間至少兩人；其他玩家透過邀請網址加入，每位玩家使用獨立帳號／瀏覽器工作階段。

開發模式使用 `npm run dev`，瀏覽器開啟 <http://localhost:5173>。資料預設保存在 `data/game.sqlite`，關閉分頁或重啟不會清除。不得將 `data/`、`.env` 或真實帳號資料提交至 Git。

## AI 模式

沒有金鑰時明確顯示「規則試玩模式」。快捷選項可以完成全部任務；自由輸入僅做關鍵字對應，不能用它證明 AI GM 品質。

複製 `.env.example` 為 `.env`，在本機檔案或部署環境的秘密設定中配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 與 `OPENAI_MODEL`，重啟後端。不要把金鑰放進前端或貼在聊天。服務需支援 `/chat/completions`、JSON object 輸出及 `max_tokens`。`AI_TIMEOUT_MS` 上限 20000。

真實模型啟用後：自由行動會呼叫模型轉為受限意圖；擲骰結算後會生成旁白。模型錯誤不重擲、不重複傷害，必要時退回固定敘事。畫面始終保留正式規則結果；AI 旁白只是額外描述。AI calls 與 token 保守預留上限按場次累計，接續第二章不會重置預算；達上限仍可用快捷選項。

本環境尚未配置模型金鑰，亦未開通選定模型 API 網域，因此目前真實 AI 驗證為 **BLOCKED**。HTTP fixture 僅驗證 API 契約，不是模型品質證據。設定完成後按 [驗證紀錄](docs/verification.md) 的真實模型驗證清單執行。

## 遊戲規則與內容

- 原創低魔霧海世界，三種種族、三種職業；力量／敏捷／洞察共 6 點，各項 0–4，種族另有 +1 加值。
- 自然 1 大失敗、自然 20 大成功，其餘骰點＋加值 ≥ DC 成功。大失敗損失 2 HP 並讓下一次檢定 -2；大成功額外獲得 3 金幣。
- 探索輪流行動；移動需要在線隊友一致確認。全員離線暫停；斷線超過 60 秒自動跳過／防禦。房主離線後可由最早在線成員接任。
- 港口與濕地取得線索；必要線索在兩次一般失敗後可取得，避免卡死。燈塔可用誓言交涉或戰鬥通過。
- 普通攻擊 5 傷害、職業技能 8 傷害（專注 -1），大成功額外 +4；守衛每次反擊 3 傷害，防禦時 1。藥水回復 8 HP。
- 完成第一章後可接續第二章，保留角色、金幣、裝備與履歷。第二章是人工設計的回訪模板，不是無限劇情生成。
- [完整內容與規則](docs/rules.md)。

## 網路遊玩

第一版以單一長駐 Node 程序執行，Socket.IO 推送狀態；所有人連到同一後端。區網可使用主機的 LAN IP 與 port 3001；同一手機瀏覽器即可完成所有操作。跨網路需自行部署可達的 HTTPS 服務，反向代理同時轉送 HTTP 及 `/socket.io` WebSocket。

部署時設定 `PUBLIC_ORIGIN=https://你的網域` 與 `COOKIE_SECURE=true`。保持應用與 API 同來源；不需要在玩家裝置配置 AI key。SQLite 所在磁碟必須可持久寫入；不要水平啟動多個獨立副本。此版尚未提供公開服務所需的密碼重設、完整營運管理與負載驗證，適合受邀測試。

## 驗證

```bash
npm run build
npm test
npm run test:e2e
```

瀏覽器測試預設使用 `/usr/bin/chromium`；其他系統可設定 `CHROMIUM_PATH`。CI 使用 Playwright 安裝的 Chromium。測試啟動 port 3101 並使用獨立的 `data/browser-test.sqlite`，不會修改正式遊戲存檔。`test-results/` 內含桌面／平板／手機截圖，`playwright-report/` 含結果。

測試涵蓋四種骰點判定、完整探索與戰鬥、任務接續、重複請求、越權、存檔重開、AI 故障／預算、HTTP 與 Socket.IO、四個隔離瀏覽器合作。真實模型、異地網路、人工體驗與每場成本另行驗證，不能由這些測試推論。

## 資料與架構

`src/`：React 介面及 SVG 地圖；`shared/`：型別與內容；`server/engine.ts`：遊戲規則與狀態機；`server/store.ts`：SQLite 交易與帳號；`server/gm.ts`：模型契約；`server/app.ts`：HTTP、Socket.IO 與權限。

本版對原規劃的收斂：Express 取代 NestJS、SQLite 取代 PostgreSQL，以降低單機原型啟動成本。僅單一後端實例，日後需要水平擴展時再遷移資料層與房間協調。使用帳號密碼取代電子郵件服務；密碼以 scrypt 雜湊，登入憑證以 HttpOnly／SameSite cookie 保存，資料庫只存 token hash。

同一交易保存房間狀態、事件與請求去重紀錄；WebSocket 全量推送供小房間使用，按事件序號補讀 API 也可使用。AI 執行時不持有資料庫交易；工作 ID 可拒絕逾時／重啟後的遲到結果。內容版本不符時拒絕讀寫，不擅自套用新版規則。

備份：停止服務後複製 `data/` 整個目錄（包含 SQLite WAL／SHM），恢復時先停服務再還原。執行中的備份應改用 SQLite backup 工具；不要只複製正在寫入的主檔。自動化測試已驗證關閉／重開資料庫後保留檢定與結果。

## 已知範圍限制

固定地圖、固定裝備、兩章內容、隊伍不分隊、任務開始後不加新玩家。技能第一版只有數值與主要屬性差異；沒有進階狀態堆疊與完整 D&D 系統。未做 AI 立繪、TTS、種子地圖、硬體、店面、付款、社群與離線 AI。退出成員的永久席位移除／重分配尚未實作，可離線保留並自動跳過；角色倒下後不刪資料。公開網路測試須另確認網域、憑證與服務部署。
